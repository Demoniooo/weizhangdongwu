# 《达拉崩吧》分镜方案 A：摄影/连贯派，「一台摄影机走完一本书」

> 分镜师：方案 A（摄影/连贯派）。时间一律用默认时间轴（原版 3:28.1）的 cue 默认秒，数值取自 `docs/cues.md`。
> 本文只描述画面，不含歌词原文。画面文字只用这几类：名字、≤5 字的短对白/拟声、自拟界面字、听岔梗五个名词、片尾署名。
> 字体实测（assets/fonts）：四套字体都**没有**「囍 ★ ♥ ♪ ✓ ∞」，这些一律用路径画；黄油体和小薇**没有**间隔点「·」，要用间隔点时改用快乐体或画一个圆点。名字字形等宽（765/1000），名字排版一律按"逐字定格"放置（方便逐字动画），不要整串 fillText。

## 1. 一句话视觉主张 + 核心卖点

**主张：全片只用一台摄影机。它先推进一本合着的绘本，沿一条红色虚线走完纸上王国，最后退出书页，看着书合上。208 秒里没有一处无动机的剪接。**

核心卖点（8 条）：

1. **33 个镜头连成一条长镜头**。镜头拆分只为方便写代码。同一地点内的拆分一律做「隐形接缝」：交接帧的机位、角色位置、颜色完全一致。换地点时一定用有物理动机的转场，包括翻页、告示扑镜、心形遮罩圈、卷轴滚镜、洞口推穿、台口变形、围巾擦屏、圆窗穿越。
2. **书开到书合是一个闭环**。开场俯视皮面书封，书翻开到 90° 就成了舞台：后页是天幕，书脊是地平线，前页是地面，然后推进书里。结尾反向拉出、合书，用同一张书封做片尾卡。
3. **一张地图有三种形态，共用一套地理坐标**。立誓时是招募告示背面的蜡笔草图，间奏一是羊皮纸王国全图，旅途和归途里折成右上角的 RPG 小地图。三种形态的地标位置完全一致。
4. **18 秒出征一镜到底（V04–V13）**。白马向右狂奔，镜头长距离横移，穿过 6 个区。天色按"路程"连续变化：清晨、正午、金色午后、风雪、月夜、洞紫。每个换区点由一个前景大物体从镜头前扫过，把接缝藏住，依次是城门柱、大橡树、半雪松、雪崖、黑树干。
5. **形状匹配链**：洞口和龙眼、宽银幕黑边和剧场台口、台口上下沿和龙嘴（咬）、城堡外圆窗和王座厅内圆窗、夕阳和月亮（隔着一次翻页）、卷轴与红毯、道路。
6. **名字是实物，每次换一种材料**。
   - 勇者名：撑破对话框、挤爆取名框、从国王嘴里吐出的纸串打结，最后变成三枚大印。
   - 龙名：龙身 13 节背板、火焰字、砸落的石碑墙。
   - 回合制：剧场名字牌走马灯、名字之剑。
   - 归来后：公主名是花瓣环，城名是 13 座塔的旗；传令卷轴、婚礼横幅；最后取名框刚好装下三个字。
7. **红围巾全程在场，而且推动叙事**：书签、拖地长围巾、片名下划线、吸收众人希望后发光变长、被打出破洞、缠在名字之剑剑柄上、擦屏开启归途、婚礼跳舞时把两人缠在一起、孩子的一截短围巾、合书后挂在书外的书签。
8. **13 座塔从第一帧就在**。前奏立体书弹出时，王城 13 座塔逐个立起（只埋伏笔，不解释）。凯旋时每座塔升起一面旗，一旗一字，连起来正好是城名。

## 3. 逐镜头分镜表

### 3.0 读表约定

- **机位**写作 `cam(x, y, 变焦[, 滚转°])`，坐标是该地点主体层（depth 1）的世界坐标，(960,540,1) 与屏幕重合。各地点的世界坐标与固定布局见第 4 节。`A → B（缓动，起–止秒）` 表示运镜。缓动沿用 ease.js：运镜用 glide，甩镜用 whip，冲击推近用 snap，入场用 outBack/spring。
- **屏幕落点**：直接给出主体在 1920×1080 屏幕上的位置和高度，写代码时用 toScreen 反解机位即可。机位数字与屏幕落点冲突时，以屏幕落点为准。
- **景别**：
  - 大全景：变焦 0.6–0.8
  - 全景：1.0，勇者高 260px
  - 中景：约 1.6，勇者高 420px
  - 近景：约 2.2
  - 特写：约 3.6，勇者头部 360px
- **图层**：远（depth 0.1–0.35）、中（0.5–0.8）、主（1.0）、前（1.3–1.5，blur 3–6）、界面（屏幕空间，不跟机位）。
- **时间**：`[起, 止)` 是镜头激活区间（默认秒），包含转场重叠。转场由后一镜负责画，前一镜在重叠期内照常画。
- **隐形接缝**：前后两镜不重叠，前镜末帧与后镜首帧的机位、角色、颜色完全相同，观众看不见切点。这类点**不登记**进 story.cuts，保证运动模糊连续。
- 每个关键动作都标"@秒"，一律落在 cue 上，或 cue 后 ≤0.15s。只卡 cue，不卡拍。

## 4. 连贯设计

### 4.1 全片机位体系

- **摄影机是一台多平面摄影台**，只做四种运动：横移（x）、升降（y）、推拉（变焦）、少量滚转。伪 3D 只允许出现在这几处：
  - 两平面俯仰：S01、S32
  - 翻页：S31
  - 折纸：S13、S14
  - 花瓣环绕：S26
  - 视差假环绕：S22 慢动作、S30 跳舞
- **景别标准**（勇者身高 / 头高）：
  - 大全景：变焦 0.6–0.8
  - 全景：1.0，身高 260px
  - 中景：约 1.6，身高 420px
  - 近景：约 2.2
  - 特写：3.6 以上，头高 360px
  - 同一地点用同一套预设（A_*、TR_*、CAVE_*），换镜时只能在预设之间运动。
- **运动词汇**：
  - glide：常规运镜。
  - whip：甩镜，时长 ≤0.35s，必须带速度线和运动模糊。只用在 N1→K1、N3→H1、V16、Q1、大战坠落、E03 这几处。
  - snap：冲击推近。
  - 静止镜头也要叠 drift（振幅 4–6，速度 0.35）。
- **机位只"死"两次**：O02 世界变成插画、O04 时间流逝。规则是"只有世界变成一幅画、或者时间被压缩的时候，摄影机才停"。
- **滚转（荷兰角）只用在 5 处**：S01 书桌 −3°、N3 国王乱了 +6°、D3 巨龙压迫 −3°→−5°、大战慢动作 ±2°、跳舞 ±1.5°。其余一律水平。
- **宽银幕黑边只出现一次**：大战对峙（134.2–137.92），随后长成剧场台口。
- **速度上限**：镜头内横移 ≤1400px/s（S15 月光段 1200 是全片最快）；超过 3000px/s 的一律按甩镜处理。
- **情绪推近点**：深吸气（L16）、龙眼（V14）、公主花环（E02）、取名面板（O06）。这四处推得最慢、最近。

### 4.3 屏幕方向

- **去程左→右，归程右→左**。
  - 左→右：S04 勇者从左入画；S05 和 S13 路线从左往右画；V02 白马从左进来；S15 全程向右；山洞入口在左；S22 勇者向右进攻；B10 名字之剑向右生长。
  - 右→左：E03 围巾从右往左擦屏；瞬移甩镜向左；E04 白马从右边向城门奔来。
  - O07 卷轴从左下的城堡铺向右上的地平线，把整部片的方向再走一遍。
- **对峙轴线**：勇者永远在画左。国王、巨龙、婚礼上的公主和国王都在画右。唯一的例外是 O01 跳舞转圈时两人临时换位，曲终时换回来。
- **反派的攻击方向**：龙的一切攻击物都从右往左走，包括火焰字、火柱、尾扫、扑咬；勇者的一切攻击都从左往右走，包括刀光和名字之剑。
- **蜥蜴的朝向**：巨龙阶段始终面朝左；缩成蜥蜴、爬上勇者肩头后改为面朝右（E02 起），用朝向交代它换了阵营。
- **阅读方向 = 运动方向**：所有"动态出现"的名字，都按阅读顺序、沿运动方向出现。
  - 勇者名①：对话框逐字向右打出。
  - 龙名①：阅读式右摇。
  - 龙名②：火焰字最先喷出的飞得最远，落定后从左往右正好是正序。
  - 龙名③：石碑从左往右砸。
  - 名字之剑：向右长。
  - 城名旗：从左往右升。
  - 捷报纸卷：向右滚。
  - 婚礼横幅：鸽子从左往右拉。
  - 不允许出现"倒着揭示"的名字。

## 5. 名字梗设计

总原则：
- **名字每出现一次，就换一种"材料"，卷入的范围更大一圈，镜头也换一种运动。**
- 升级有三个维度：
  - 字号：100 → 200px
  - 卷入范围：一个框 → 一块面板 → 一个人 → 整个朝廷 → 整个洞穴 → 整座剧场 → 整座城 → 整条旅途
  - 破坏程度：撑破 → 挤爆 → 打结 → 盖章封印
- 每一段都卡在 a/b/c 的分段 cue 上。

## 6. 最难做、最容易翻车的 5 个镜头

### ① S15 一镜到底出征（80.22–99.60，19.4s）

**风险**
- 5 层视差连跑 19 秒，性能吃紧。
- 换区处露出接缝。
- 事件按"位置"摆放，结果和 cue 对不上。
- 月光段 1200px/s，前景树干会糊成一片或者闪烁。

**规避**
1. **事件按时间定，位置由时间反推**。比如宝箱的世界 x = 勇者在开箱时刻的世界 x + 180，不要先摆位置再算时间。这样 cue 的准确度不会被运镜曲线牵连。
2. camX(T) 用单调三次样条，把第 3 节关键帧表写成数据。S15、S27、小地图三处共用这一个函数。
3. 区函数只画视窗外扩一屏以内的部分；每帧 layer ≤7 个；天空直接画，不开 layer。
4. 每个换区点都要有一个遮挡物，而且它过屏幕中线的那一帧，前后两区都要画完整。换区交给遮挡物，不交给淡入淡出。
5. 月光段前景树干如果子帧运动模糊太慢，改成手画速度条纹（拉长的深色带），效果一样。
6. 验收：`sheet --from 80 --to 99.6 --every 0.25`，逐个 cue 看关键动作是否在 ±0.15s 内。

### ② S13–S14 地图展开 → 画红线 → 折成小地图，同时广场立起（64.8–74.4）

**风险**
- 伪 3D 折页看起来"扁"，或者穿帮。
- 几块折页同时动，画面乱。
- 小地图和大地图对不上。
- 城堡图标和立起的城堡在交接那一刻错位。

**规避**
1. 每块折页只绕一条轴缩放，过 90° 时换成背面色（paper2），折痕处加一道 shade，再加一道随角度变化的投影。
2. 同一时刻最多两块折页在动（时间表已经错开）。
3. 地图内容只写一个 `drawMap(g, {scale, detail, routeP})`，大地图、小地图、折叠中的地图都调它，所以永远对得上。
4. 城堡图标到广场城堡的交接：先定"交接瞬间的屏幕框 (980,330) 宽 300"，两边分别反解机位，不要各自凭感觉。
5. 广场景片立起复用 S01 的铰链函数 `hinge(p)`。

### ③ S01 书封翻开 + 俯仰转正 + 立体书弹出（0–10.0）

**风险**
- 两平面投影做出来像"压扁"而不是"转动"。
- 立体件的底边在转正过程中滑离书页。
- 和 S02 交接时书内画面跳一下。

**规避**
1. 写一个 `projectBook(elev)`，返回两组变换：地面页纵向乘 sin，竖立件纵向乘 cos。所有立体件的底边都钉在"地面页投影后的位置"上。
2. 用光来卖转动：地面页亮度随 sin(仰角) 变化，书封投影长度随角度变化。
3. 转正只用 2.2 秒，glide 缓动，不要拖长。
4. 8.0 秒之后书内画面直接调用 S02 的王城绘制函数和同一组机位。验收时在 9.2 / 9.5 / 9.9 三个时刻各渲染一张"只开 S01"和"S01 加 S02"的静帧，对比是否一致。
5. S32 合书时直接反向调用这套函数，不要写第二套。

### ④ S22 大战一镜到底（120.97–137.92，16.95s）

**风险**
- 17 秒动作戏变成一锅粥，看不清谁在干什么。
- 盘柱段前后遮挡出错。
- 慢动作破坏确定性。
- 左右分色变成全屏滤镜，太贵。

**规避**
1. 第 3 节那张拍子表就是法律：每一拍一个关键姿势，一个清楚的剪影。勇者和龙都用"姿势库"（跑、跳、劈、落地、架势、对撞）加插值实现。
2. 左右轴线锁死：勇者在左、龙在右，任何一拍都不越线。
3. 盘柱：按每节龙身绕柱的角度分到"柱前 1.1 层"和"柱后 0.9 层"两个 layer，勇者跟着所在的那一节换层。
4. 慢动作用局部时间 τ(T)：分段线性，129.0–129.9 斜率 0.3，本拍所有动画都在 τ 上采样。整个函数仍然只依赖 T。
5. 分色只用两个半屏遮罩叠 tint，额外 layer ≤2 个。
6. 超预算时的降级：先删"笼顶"那一拍（改成从笼侧跃过），其余不动。

### ⑤ S25 名字之剑：生长、横摇、破框、后拉、劈下（153.78–157.80）

**风险**
- 3.4 秒内同时发生 13 个字上剑、镜头横摇、捅破幕布、后拉、竖剑顶破顶幕，节奏容易乱。
- 字的位置跟着横摇抖动。
- 幕布"前后"关系穿帮。

**规避**
1. 一切都算在剧场自己的坐标系里：第 i 个字的位置 = 护手 x + 60 + i·130；横摇量 = 剑尖 x − 1500。字跟着剑身走，不单独跟机位。
2. 台口拆成"剑后"和"剑前"两层，撕口用预先画好的多边形，剑尖越过幕线时才显示。
3. 后拉终点 0.62 倍，保证 1900px 的剑完整入画（约 1180px 宽）。
4. 在 154.8 / 155.6 / 156.4 / 157.1 各出一张静帧，检查字是否一直正立、可读。
5. B11 的冲击只做一次最大号的，不要在生长过程中加震动，把力气留给劈下那一刀。

### 次级风险（一句话提醒）

- **S18 龙身背板**：S 形身体上的 13 块牌必须等弧长取点，字永远正立，牌的旋转限制在 ±15°，否则读不出来。
- **S26 花瓣环**：阅读顺序靠"在最前方诞生"来保证。背面花瓣只用一个 blur layer，不要逐片 filter。
- **S27 瞬移甩镜**：0.5 秒穿过整条旅途，不要真把 6 个区都画出来，用一条预先算好的"色带加速度线"代替。
- **字形缺失**：囍 ★ ♥ ✓ ∞ 四套字体都没有，一律用路径画；「·」只有快乐体有。验收时注意有没有回退字体混进来。
